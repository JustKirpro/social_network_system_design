# Социальная сеть для путешественников
Домашнее задание [курса по System Design](https://balun.courses/courses/system_design)

### Функциональные требования
* Публикация поста с фотографиями, небольшим описанием и местоположением;
* Оценка и комментарии постов других путешественников;
* Подписка на других путешественников, чтобы следить за их активностью;
* Поиск популярных мест для путешествий и просмотр постов с этих мест;
* Просмотр ленты других путешественников и ленты пользователя, основанной на подписках в обратном хронологическом порядке.

### Нефункциональные требования
* Через год DAU в районе 10 000 000 и будет расти;
* Аудитория стран СНГ;
* Сезонность присутствует - периоды отпусков (лето, новогодние и майские праздники), в эти периоды нагрузка вырастает в полтора раза;
* Доступность 99.9% (допустимый downtime не более 8 часов 45 минут в год);
* Должны поддерживаться мобильные приложения для iOS и Android, а также web-версия для Chromium, Safari и Firefox;
* Данные хранятся всегда;
* Активность пользователей:
  * в среднем каждый пользователь пишет 1 пост в неделю;
  * в среднем в одном посте 3 фотографии (средний размер фотографии 1 MB);
  * в среднем в посте 400 символов;
  * в среднем каждый пользователь ставит 10 реакций постам других путешественников в день;
  * в среднем каждый пользователь пишет 1 комментарий постам других путешественников в день;
  * в среднем в комментарии 50 символов;
  * в среднем каждый пользователь подписывается на 2 других пользователей в неделю;
  * в среднем каждый пользователь ищет 1 место для путешествий в неделю;
  * в среднем каждый пользователь открывает ленту 5 раз в день;
  * за одно открытие ленты пользователь просматривает в среднем 20 постов;
  * в среднем пользователь открывает комментарии к 5 постам в день;
  * у одного поста в среднем 20 комментариев;
* Лимиты:
  * в одном посте может быть не более 10 фотографий;
  * размер одной фотографии не более 3 MB;
  * в описании одного поста может быть не более 2 000 символов;
  * пользователь может создавать не более 100 постов в день;
  * пользователь может подписываться не более чем на 100 других путешественников в день;
  * пользователь может оставлять не более 1000 реакций на посты других путешественников в день;
  * пользователь может оставлять не более 100 комментариев на посты других путешественников в день;
  * длина одного комментария может быть не более 2 000 символов;
  * пользователь может искать место для путешествия не более 100 раз в день;
* Тайминги:
  * создание поста - не более 1 секунды (без учёта полной обработки фотографий);
  * загрузка ленты с 20 постами - не более 0.5 секунды;
  * поиск мест для путешествия - не более 2 секунд;
 
### Модель данных
Для дальнейшего расчёта трафика округлил размеры сущностей для более удобных расчётов

Пост ≈ 1 KB:
 * id - 8 B;
 * user_id - 8 B;
 * place_id - 8 B;
 * description - 800 B (400 как среднее количество символов в посте * 2 байта на символ в среднем);
 * reactions_count - 4 B;
 * created_at - 8 B;

Фото ≈ 128 B:
 * id - 8 B;
 * post_id - 8 B;
 * url - 100 B;
 * order - 4 B;
 * created_at - 8 B; 

Комментарий ≈ 128 B:
* id - 8 B;
* post_id - 8 B;
* user_id - 8 B;
* text - 100 B (50 как среднее количество символов в комментарии * 2 байта на символ в среднем);
* created_at - 8 B;

Реакция ≈ 32 B:
 * post_id - 8 B;
 * user_id - 8 B;
 * created_at - 8 B;

Подписка ≈ 32 B:
 * follower_id - 8 B;
 * followee_id - 8 B;
 * created_at - 8 B;

Место ≈ 256 B:
 * id - 8 B;
 * name - 256 B;
 * latitude - 8 B;
 * longitude - 8 B;

### Нагрузка
#### Запись:
* Публикация поста = 10 000 000 / 86 400 / 7 ≈ 17 RPS;
* Реакции на посты = 10 000 000 / 86 400 * 10 ≈ 1157 RPS;
* Комментарии к постам = 10 000 000 / 86 400 * 1 ≈ 116 RPS;
* Подписки = 10 000 000 / 86 400 / 7 * 2 ≈ 33 RPS;

#### Чтение:
* Открытие ленты = 10 000 000 / 86 400 * 5 ≈ 579 RPS;
* Просмотр комментариев = 10 000 000 / 86 400 * 5 ≈ 579 RPS;
* Поиск мест = 10 000 000 / 86 400 / 7 ≈ 17 RPS;

В пиковые периоды из-за сезонности нагрузка может возрастать примерно в 1.5 раза

### Трафик:
#### Метаданные:
##### Запись:
* Публикация поста = 17 RPS * 1 KB ≈ 17 KB/s;
* Реакции на посты = 1157 RPS * 32 B ≈ 36 KB/s;
* Комментарии к постам = 116 RPS * 128 B ≈ 15 KB/s;
* Подписки = 33 RPS * 32 B ≈ 1 KB/s;

##### Чтение:
* Открытие ленты = 579 RPS * (1 KB + 3 * 128 B) * 20 ≈ 15 MB/s (при открытии ленты в среднем получаем 20 постов, в каждом в среднем 3 фото);
* Просмотр комментариев = 579 RPS * 128 B * 20 = 1.4 MB/s (в каждом посте в среднем 20 комментариев);
* Поиск мест = 17 RPS * 256 B ≈ 4 KB/s;

#### Медиа:
##### Запись:
* Публикация поста = 17 RPS * 1 MB * 3 ≈ 51 MB/s (в среднем в одном посте 3 фотографии, средний размер фотографии 1 MB);

##### Чтение:
* Открытие ленты = 579 RPS * 1 MB * 3 * 20 ≈ 34 GB/s;

Это трафик с учётом возвращения полноразмерных фотографий, предположим, что средний размер фотографии, возвращаемой пользователю при просмотре ленты ≈ 300 KB, тогда трафик снижается до ≈ 10 GB/s.

### Хранение данных:
#### Метаданные:
* Capacity = 69 KB/s * 86 400 * 365 ≈ 3 TB;

##### HDD (Capacity 2 TB, Throughput 100 MB/s, IOPS 100):
* Дисков для Capacity = 3 TB / 2 TB = 2;
* Дисков для Throughput = 90 KB/s / 100 MB/s = 1;
* Дисков для IOPS = 2500 RPS / 100 = 25;

##### SSD SATA (Capacity 2 TB, Throughput 500 MB/s, IOPS 1000):
* Дисков для Capacity = 3 TB / 2 TB = 2;
* Дисков для Throughput = 90 KB/s / 500 MB/s = 1;
* Дисков для IOPS = 2500 RPS / 1000 = 3;

##### SSD NVMe (Capacity 4 TB, Throughput 3 GB/s, IOPS 10000):
* Дисков для Capacity = 3 TB / 4 TB = 1;
* Дисков для Throughput = 90 KB/s / 3 GB/s = 1;
* Дисков для IOPS = 2500 RPS / 10000 = 1;

**Итог**: для хранения метаданных можно использовать 25 HDD, 3 SSD SATA или 1 SSD NVMe.

Я выбираю 3 SSD SATA, так как для метаданных ограничивающим фактором являются IOPS. Использование 25 HDD слишком сложно в поддержке, а SSD NVMe для такой нагрузки выглядит избыточным.

#### Медиа:
* Capacity = 51 MB/s * 86 400 * 365 ≈ 1600 TB;

##### HDD (Capacity 8 TB, Throughput 100 MB/s, IOPS 100):
* Дисков для Capacity = 1600 TB / 8 TB = 200;
* Дисков для Throughput = 10 GB/s / 100 MB/s = 100;
* Дисков для IOPS = 2500 RPS / 100 = 25;

##### SSD SATA (Capacity 32 TB, Throughput 500 MB/s, IOPS 1000):
* Дисков для Capacity = 1600 TB / 32 TB = 50;
* Дисков для Throughput = 10 GB/s / 500 MB/s = 20;
* Дисков для IOPS = 2500 RPS / 1000 = 3;

##### SSD NVMe (Capacity 64 TB, Throughput 3 GB/s, IOPS 10000):
* Дисков для Capacity = 1600 TB / 64 TB = 25;
* Дисков для Throughput = 10 GB/s / 3 GB/s = 4;
* Дисков для IOPS = 2500 RPS / 10000 = 1;

**Итог**: для хранения медиа можно использовать 200 HDD, 50 SSD SATA или 25 SSD NVMe.

Я выбираю HDD, так как для хранения медиа ограничивающим фактором является объём хранения, а не IOPS или throughput. Для такой подсистемы важнее минимизировать стоимость хранения больших объёмов данных, поэтому HDD выглядит наиболее разумным вариантом.
